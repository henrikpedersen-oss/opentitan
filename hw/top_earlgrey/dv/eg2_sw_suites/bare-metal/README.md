# Bare-metal software suite

Every chip test that runs as a C program on the test ROM, without an operating system, on the EG2
SystemC model: OpenTitan's chip tests and EG2's. It runs in minutes, against hours on the RTL.
Run from eg2_top_verification, with this tree as its `eg2/`:

```
make eg2sim                 # the model, from hw/top_earlgrey/dv/eg2_model (lowRISC/ot-model)
make sw-suite-bare-metal    # every test; SUITE_JOBS=, PATTERN=
```

The chip test images are the newest `*_sim_dv.elf` in this tree's `bazel-out/` (dvsim builds them;
`../env.sh` says where the model and the output are).

Each test ends in one of six outcomes, from the model's exit status or suite policy: `pass`; `must-fail` (an
`_inject_fail` variant failed, as it must; the reports show it as "pass (must fail)"); `fail` (the test finished and reported a failure);
`model-stop` (the model stopped the run because the test needs something it does not model, most
often a wake-up from WFI or low power that only a testbench gives, or OTBN); `on-hold` (the test
needs the production mask ROM or ROM_EXT flow); or `no-end` (the test
did not finish within the instruction limit, typically waiting for stimulus from a testbench). The
report gives the model's reason for every outcome that is not a pass. `expected.txt` holds the outcome each test must give; the suite
fails when a test's outcome changes, and lists tests not in the file as new.
`make sw-suite-bare-metal UPDATE=1` rewrites `expected.txt` from the run: review the diff.

The files beside the runner:

| File | What it holds |
|---|---|
| `expected.txt` | The outcome each test must give |
| `categories.txt` | The report's categories, `<area>: <block>`, by test-name pattern |
| `bench.txt` | What the chip bench would drive for a test, as eg2sim arguments (symbols, peripheral stimulus, the debugger's actions through rv_dm); `{image:<path>}` names another image of the Bazel output (an SRAM program the debugger loads) |
| `bench_checks.txt` | The tests whose bench sequence checks something itself: their passes show as "pass (bench checks not run)". Generated by `gen_bench_checks.sh` from the EG2 fork's test lists |
| `bench_checks_run.txt` | Entries from `bench_checks.txt` whose checks are reproduced by model stimulus, so they are ordinary checked passes |
| `on_hold.txt` | Tests not run until their production mask-ROM or ROM_EXT dependency is available, with the reason |
| `known.txt` | Tests that fail on purpose until a finding is resolved, or are under investigation: shown with "(known)" |

A pass means every check in the test's own software held; it says nothing about the RTL, and
nothing about checks the chip bench makes (`doc/sw_test_suites.md`, "What a pass means").

The test images come from this tree's Bazel build (`bazel-out`, dvsim builds them).
Output: `scratch/sw-suites/bare-metal/` in eg2_top_verification (`report.txt`, `results.txt`, a log directory
per test). Each test's directory has `rerun.sh`, the exact run to repeat by hand; options given to it
are added after the suite's, so `rerun.sh --max-insns 2000000000` reruns a test with ten times the
instruction limit (logs in `<test>/rerun/`). The report ends with that command for every no-end test.
